# R3 UNKNOWN 分诊与验证预算 PRD

状态：proposed，开发前可审查规格。日期：2026-10-21。分支：feat/r3-unknown-triage。本文件不代表实现或实验完成。

## Problem Statement

验证未完成、工具域外和命题错误容易混为一谈；固定重试既可能浪费预算，也可能产生未经支持的可信标签。

## Solution

先交付明确结果类型和原因感知回退，再在真实验证义务上比较翻译、求证、补充可信前提和重推的预算分配。

比赛用途是可解释系统设计、稳定交互与规范证据；学术价值需要独立实验。官方路径与默认开关遵守 AGENTS.md。

## User Stories

1. 作为数学使用者，我希望区分候选有效和完整命题被证明，以便理解验证范围。
2. 作为展示者，我希望工具域外和超时有不同说明，以便展示稳定性。
3. 作为维护者，我希望 UNKNOWN 不触发无限重试，以便保护预算。
4. 作为实验者，我希望同一失败义务接受不同干预，以便比较预算价值。
5. 作为研究者，我希望编译成功与语义忠实分别评价，以便防止翻译改变命题。
6. 作为实验者，我希望所有模型仍为 S2，以便符合服务约束。
7. 作为展示者，我希望 Lean 未就绪时仍能展示受限工具的真实能力，以便不阻塞交付。
8. 作为审查者，我希望证书和失败原因均能追溯到同一命题，以便验证结论。

## Implementation Decisions

- 结果分开保存 outcome、reason、scope、certificate_ref；UNKNOWN、SKIPPED 与 REFUTED 不可互换。
- 优先复用 polynomial_check 的已限定适用范围；候选代回通过不代表完整解集。
- 形式研究先用可信原生 Lean 命题；S2 formalizer/prover 与固定 kernel，NL→Lean 需额外语义忠实审查。
- 简单错误码规则是必须击败的基线，翻译/证明/重推费用均进入同一调度账本。

## Testing Decisions

公开 Tool Registry invoke 与 Verification/报告合同：捕捉结果类型、适用域、证据对象和有限回退；数学语义忠实度须用另行可信标注。

只验证公开行为，外部 API 可注入确定性替身；替身与回放不证明 live 能力。每个切片先有可执行验收，再最小实现和相关回归。实验真值、预算及数据分组遵守总计划，不以自评替代独立评价。

- [ ] 域外、超时、缺依赖和反例有不同类型；UNKNOWN 不被当成假命题。
- [ ] polynomial 候选有效和覆盖 unknown 同时保留。
- [ ] 每条形式证据绑定具体命题与环境；不允许空洞证明或未审查前提。
- [ ] 有限重试耗尽后进入明确待复核状态，原解答不丢失。

## Out of Scope

- 改变官方 baseline、默认开启研究策略或引入第二个模型服务。
- 一开始就开展大规模 RL、无上限多 Agent 或完整自然语言形式化。
- 以少量演示题的效果宣称普适正确率或理论保证。

## Further Notes

研究假设：部分 UNKNOWN 的原因可以预测下一次预算干预的可信收益，分诊能够优于固定错误码规则。

近邻边界：HERMES 已有验证失败反馈和固定翻译/证明预算，SSV 已有弱强验证与预算思想；新增应是失败原因与干预价值的可验证关系。

工程保留与停止：如果大多数 UNKNOWN 无法被有限预算恢复，保留错误分型和规则回退；如果翻译成本吞掉收益，限制适用域；仅提高编译率不作为数学可靠性成果。

基线：不形式化流程、固定翻译/证明预算、按错误码固定分流、只加 formalizer、只加 prover、平均或随机分配。

评价：UNKNOWN 转可信证据率、每单位成本的可信证书、语义不忠实假通过率、最终解题正确率、工具域外覆盖、回退和失败分布。

依赖：公共 setup S1–S5 的对应能力通过；实际依赖按技术文档中的 ticket 图执行。PR 目标为 develop，默认启用与学术晋升另行判定。
