# R1 同模型局部动作收益路由 PRD

状态：proposed，开发前可审查规格。日期：2026-10-21。分支：feat/r1-action-value-routing。本文件不代表实现或实验完成。

## Problem Statement

当前 Agent 缺少按可见状态选择下一步动作的可比较合同；多角色和更多调用本身不能证明更有效。

## Solution

在固定 Intern S2 和总资源条件下，把继续、局部重推、适用工具检查做成可关闭动作；先规则后学习，并在 Workbench 展示脱敏动作理由与结果范围。

比赛用途是可解释系统设计、稳定交互与规范证据；学术价值需要独立实验。官方路径与默认开关遵守 AGENTS.md。

## User Stories

1. 作为参赛展示者，我希望看到为何选择继续、局部重推或计算工具，以便清楚解释系统设计。
2. 作为数学使用者，我希望工具不适用时仍获得有明确限制的解答，以便不会被错误的通过状态误导。
3. 作为实验者，我希望同一前缀能执行同预算的不同动作，以便比较干预收益。
4. 作为实验者，我希望控制器只能看到当前信息，以便防止未来标签泄漏。
5. 作为维护者，我希望新策略关闭后没有额外模型调用，以便可回退至 B-ready。
6. 作为审查者，我希望检查有害改写和全部成本，以便收益不是靠漏算重试得到。
7. 作为展示者，我希望失败时保留已有产物及状态，以便演示不会中断为无信息页面。
8. 作为研究者，我希望简单规则也是强对照，以便明确学习机制的增量价值。

## Implementation Decisions

- 固定 intern-s2 与 thinking 模式。动作不同不称为强弱模型；工具只能来自允许的确定性 Registry。
- 决策输入是可见前缀、受限计划、完成状态、工具适用性与剩余预算；不读取隐藏推理或未来轨迹。
- 每次只选择一个动作，由一个共同调度器控制；轻量控制器优先使用 CPU 模型或规则，任何 S2 控制调用均计费。
- 同题及其所有前缀按问题分组；动作价值标签来自独立续写，有限池 oracle 只作为分析上限。

## Testing Decisions

公开 Model Adapter 与 Run/Job 报告合同：捕捉动作适用性、预算、结果身份及回退；不能证明真实动作更优。

只验证公开行为，外部 API 可注入确定性替身；替身与回放不证明 live 能力。每个切片先有可执行验收，再最小实现和相关回归。实验真值、预算及数据分组遵守总计划，不以自评替代独立评价。

- [ ] feature flag 关闭时，官方保护文件不变且无额外调用；research 结果标记清楚。
- [ ] 工具域外不调用工具，UNKNOWN 不被标成错误或通过。
- [ ] 取消或额度不足不启动新动作；失败与回退全部入账。
- [ ] 报告绑定最终答案及适用验证，保留有害改写和未完成样本。

## Out of Scope

- 改变官方 baseline、默认开启研究策略或引入第二个模型服务。
- 一开始就开展大规模 RL、无上限多 Agent 或完整自然语言形式化。
- 以少量演示题的效果宣称普适正确率或理论保证。

## Further Notes

研究假设：调用前可见的错误风险、工具适用性和剩余预算，能够预测不同干预的净收益；学习策略能够超过长度与完成状态规则。

近邻边界：Reflective Confidence、Decision Tokens、SEVRA、ReTool 已覆盖反思、稀疏干预、选择性验证或工具使用；新增主张必须落在同一状态下动作收益的可预测分工。

工程保留与停止：若固定策略或 B-rule 已最好，保留其实现和动作接口，关闭学习路由；若收益全来自截断补全，停止认知机制主张。统计精度不足标为 inconclusive。

基线：B-ready、优化过的 B-direct/B-long、B-rule、固定继续/重推/工具、同适用动作集合的随机路由。

评价：固定总成本下的答案正确率、错转对减对转错、有害改写率、工具适用覆盖、requests/tokens、p50/p90 时间、失败与未完成率。

依赖：公共 setup S1–S5 的对应能力通过；实际依赖按技术文档中的 ticket 图执行。PR 目标为 develop，默认启用与学术晋升另行判定。
