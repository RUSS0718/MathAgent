# R5 最终接受对象与风险审计 PRD

状态：proposed，开发前可审查规格。日期：2026-10-21。分支：feat/r5-final-acceptance-risk。本文件不代表实现或实验完成。

## Problem Statement

中间候选通过工具检查后，最终答案可能被修改；审核子集和自适应策略会使表面错误率无法代表最终交付风险。

## Solution

先建立最终产物与证据绑定、接受范围和覆盖率报告；在固定策略和可信标签下校准最终接受风险，再研究适应性扩展。

比赛用途是可解释系统设计、稳定交互与规范证据；学术价值需要独立实验。官方路径与默认开关遵守 AGENTS.md。

## User Stories

1. 作为数学使用者，我希望知道最终答案哪些部分被检查，以便合理信任。
2. 作为展示者，我希望改写最终答案后证据自动更新，以便不会展示过期通过状态。
3. 作为实验者，我希望接受与覆盖率一起报告，以便不靠大量拒答制造低错误率。
4. 作为审查者，我希望标签来源和审核概率可追溯，以便分析选择偏差。
5. 作为研究者，我希望先冻结策略再校准，以便保证与实际数据生成过程一致。
6. 作为维护者，我希望审核不足时显示待复核，以便避免给出虚假的风险保证。
7. 作为展示者，我希望追加验证不删除原报告，以便交互完整。
8. 作为实验者，我希望区分答案级、候选级和完整证明级目标，以便评价对象明确。

## Implementation Decisions

- 最终交付文本或结构化数学对象生成稳定哈希，证据只能附着于相符版本；改写使原接受标记失效。
- 接受、拒绝、待复核与证据范围分开，候选代回通过不升级为完整证明。
- 冻结 policy 后独立校准；抽查概率已知且有正下界，不使用未知选择机制的审核样本直接宣称总体风险。
- 可信标签与弱标签分别报告；S2 自评不当作独立数学真值，理论主张需要匹配的抽样与稳定性假设。

## Testing Decisions

公开 Job 最终报告与验证追加接口：捕捉最终身份、证据失效和不可覆盖的终态；风险结论另需可信标签与统计条件。

只验证公开行为，外部 API 可注入确定性替身；替身与回放不证明 live 能力。每个切片先有可执行验收，再最小实现和相关回归。实验真值、预算及数据分组遵守总计划，不以自评替代独立评价。

- [ ] 最终产物改变时旧证据不能支持新接受状态。
- [ ] 追加检查不抹除答案与原工具结果，覆盖范围可见。
- [ ] 缺少可信标签或样本不足时仅报告经验统计，不承诺真实风险上界。
- [ ] 确认集与校准集隔离；同题重复不当独立样本。

## Out of Scope

- 改变官方 baseline、默认开启研究策略或引入第二个模型服务。
- 一开始就开展大规模 RL、无上限多 Agent 或完整自然语言形式化。
- 以少量演示题的效果宣称普适正确率或理论保证。

## Further Notes

研究假设：对最终交付对象的选择性审核与校准能在保持覆盖的同时控制限定条件下的错误风险；该主张需要足够独立的可信标签。

近邻边界：SSV 与选择性预测已有验证门控、抽查及校准；增量应落在明确的最终接受目标与恢复后选择偏差处理，不能只增加 confidence 字段。

工程保留与停止：真值不足、审核概率未知、策略变动或样本不足时停止风险保证主张，保留经验报告和审核基础能力；R5 理论完成不阻塞其他模块 PR 或比赛演示。

基线：固定策略后重新校准、简单接受阈值、全部检查、静态随机抽查、满足条件的既有选择性验证方法。

评价：最终接受集合的条件错误率与上界、覆盖率、误接受/误拒绝、每个可信审核成本、标签缺失与选择概率分布。

依赖：公共 setup S1–S5 的对应能力通过；实际依赖按技术文档中的 ticket 图执行。PR 目标为 develop，默认启用与学术晋升另行判定。
