## 2. 需要升级的后端边界

[当前 HTTP 实现](../../showcase/server.py) 调用 `RunService.create_run()` 后返回 `201` 和运行结果；`GET /api/runs/{id}/events` 返回 JSON 数组，不是 SSE。没有会话聊天、Job 队列、取消及 UUID 幂等写入的前端兼容接口。v0.2 已决定迁移该入口到 Flask，但保留这些旧路径和响应语义，再增加 Job/SSE 路由。

[RunService](../../showcase/run_service.py) 与 [SQLiteStore](../../showcase/storage.py) 已提供可复用的应用服务和持久化基础；服务默认 `:memory:`，CLI 未暴露数据库路径，不能把“SQLite 测试通过”等同于“默认启动后历史永久保存”。v0.2 已决定将数据库和附件落在可覆盖的 `artifacts/showcase-v0.2/`，由单服务进程后台执行器消费；重启时未完成任务进入 `NEEDS_REVIEW`，不自动重复未知远端调用。

[LoopBudget](../../showcase/graph.py) 当前默认 8 steps、4 tools、1 retry、30 秒协作式运行上限。它不等同于可抢占远端阻塞请求的完整截止。v0.2 的异步执行、累计恢复预算与请求级超时须另作风险验证。

## 4. HTTP 兼容清单

本节记录消费端现状；v0.2 的启用范围以 [PRD](../prd/subjective-agent-platform-prd-v0.2.md) 为准。权威字段来自上述 client、[Job schema](<D:/project/CausalAgent-demopaper/chat-frontend/src/api/jobs.schemas.ts>)、[文件 schema](<D:/project/CausalAgent-demopaper/chat-frontend/src/api/files.schemas.ts>) 和 [认证 schema](<D:/project/CausalAgent-demopaper/chat-frontend/src/api/auth.schemas.ts>)。

| 接口 | 消费合同 |
| --- | --- |
| `GET /api/check_auth` | `{isLoggedIn:false}` 或 `{isLoggedIn:true,username,role?,permissions?,csrf_token?}` |
| `POST /api/logout` | `{success,error?}`；原工作区成功后回 `/` |
| `POST /api/new_chat` | 无正文；`{success,new_session_id?,error?}` |
| `GET /api/sessions` | 裸数组 `[[session_id,{preview,last_time}], ...]` |
| `GET /api/load_session?session=<id>` | `{success,messages?,error?}`；消息 `sender=user|ai`，`text` 可为文本或结构化对象 |
| `POST /api/change_session` / `/api/delete_session` | `{session_id,title}` / `{session_id}`；活动 Job 阻止删除 |
| `GET /api/files` | 裸数组；每项 `id,user_file_id,filename,mime_type,file_size,uploaded_at,last_accessed_at,access_count` |
| `POST /api/upload_file` / `/api/delete_file` | multipart 的 `file` / JSON `{file_id}`；上传返回 `{success,file?,user_file_id?,...}` |
| `POST /api/agent/jobs` | `{message,session_id,input_user_file_id:number|null,web_search_enabled:boolean,verification_mode?:"auto"|"required"|"off"}`；首建 202、同键重放 200 |
| `GET /api/agent/jobs/active?session_id=<可选>` | `{success,jobs?,error?}`；每项至少 `job_id,session_id,status` |
| `POST /api/agent/jobs/<id>/resume` | `{question_id,answer}`；返回 Job action 对象 |
| `POST /api/agent/jobs/<id>/cancel` | `{}`；返回 Job action 对象；终态冲突 409 |
| `GET /api/setting?topic=userAgreement\|userManual` | `{success,messages?,error?}`；数学版使用自身帮助内容 |

Job action 响应是 `{success,job_id?,status?,existing?,error?}`，Job 状态为 `queued/running/waiting_input/succeeded/failed/canceled`。创建、resume、cancel 都使用标准 UUID v4 `Idempotency-Key`；同一意图重试复用键，参数改变使用新键。同 Session 只允许一个活动 Job，冲突 `409 active_job_conflict`。

普通会话、文件与 active Job **没有分页合同**，不能套用管理员 cursor/limit 响应。原数组形状应保持；后续若做分页，需显式扩展 API 与前端消费协议。P0 的文件接口保留 DTO，但 capabilities 关闭上传，上传返回 `capability_unavailable`。

失败响应可用 `{success:false,error:string,code:string}`，响应头带 `X-Request-ID`。原普通端并非所有路由都返回 code，但 client 会归一化；v0.2 可以统一补齐。HTTP 200 形状不符也会变成 `invalid_response`。

认证页面属于另一套官网前端；MathAgent v0.2 使用本地自动 `AuthSession`，不提供注册。原普通请求未发送 `X-CSRF-Token`，MathAgent 搬入后的前端必须补齐该头；后端使用 HttpOnly、SameSite=Lax Cookie，并在所有状态变更路由校验 CSRF token。

## 5. SSE 与结果投影

依据：[事件 schema / parser](<D:/project/CausalAgent-demopaper/chat-frontend/src/api/events.schemas.ts>)、[Job API](<D:/project/CausalAgent-demopaper/Document/api/agent-jobs.md>)、[前端合同测试](<D:/project/CausalAgent-demopaper/chat-frontend/tests/contract/api-contract.spec.ts>)。

订阅 `/api/agent/jobs/<id>/events`，返回 `text/event-stream`；示例：

```text
id: 12
event: progress
data: {"type":"progress","step_id":"verify-1","node_name":"verify","title":"候选校验","summary":"正在代回原方程"}

```

- `node_start/progress/decision/tool_call_start/tool_call_result/node_end` 带稳定 `step_id,node_name,title`；progress/decision/result 另有摘要，node_end 另有耗时与 completed/failed。
- 业务事件有正安全整数 ID，`event` 与 `data.type` 一致；`heartbeat` 不带业务 ID。
- 首连用历史 `last_event_id`，重连用 `Last-Event-ID`；active 的最新 ID 不覆盖已经渲染到的游标。
- 合法未知事件只推进传输游标；坏包不推进；4xx/协议错误不重试，网络与 5xx 有界重连。
- `interrupt` 带公开问题和 `question_id`，进入 waiting_input；`final_result/error/canceled` 为终态。resume 继续原 Job，保留先前事件。
- 切换会话、退出和取消使旧订阅失效；事件先持久化，再推送，刷新不重跑模型。

最小文本结果映射为 `final_result.data={"type":"text","summary":"<final_response>"}`。数学报告可使用已有的 `type=report,render_mode=structured,document`，先只使用 section + markdown，展示答案、公开解法摘要、检查与限制。

无需为了流式观感编造 token 流、角色调用或思维链。后端没有真实增量时只发送阶段进展和最终结果。SSE、历史、Evidence Pack 使用同一结果来源；不能认为 Zod passthrough 接受一个字段，就代表页面已经展示它。

## 6. v0.2 设计判断与待验证事项

**已确认设计：** 最直接的产品增量是搬入普通工作区、持久异步任务、真实工具闭环，以及适用域清晰的候选检查与有限纠错。工具路径使用严格 schema 的 `polynomial_check`；`verification_mode=required` 且没有合法工具事件时进入 needs-review。长期记忆、多 Solver、Debate、RSI、搜索和分布式先不叠加。

**需风险验证：** Intern 工具协议与 continuation；Flask 迁移后旧 Showcase 合同保持；LangGraph / SQLite 的后台执行与重启；本地 AuthSession 与 CSRF；KaTeX 安全渲染；P1 PNG 在浏览器上传后能进入同一个 Run；受限结构化数学检查能识别错误且不误报通过。以上都是 v0.2 要验证的假设，本轮未执行这些实验。

**数学证据边界：** `polynomial_check` 使用变量、有理系数数组、实数或有理区间定义域和候选根；它只做精确代回、重复项和定义域检查，不检查完整解集。候选检查通过时显示 `candidate_status=pass`、`coverage_status=unknown`；形式化失败、超出定义域或工具不可用时返回 unknown，不把工具成功当作数学正确。

## 7. 已确认的 v0.2 决策

| 决策 | 结论 |
| --- | --- |
| 部署 | 单用户 loopback；AuthSession 自动创建；logout 清 Cookie，历史 ChatSession 保留。 |
| 前端来源 | 搬入 CausalAgent `chat-frontend` 到 `showcase/frontend/chat-frontend/`；保留 MIT 版权与许可证；移除因果图、RAG、搜索、管理员入口和因果文案。 |
| 后端入口 | 将 `showcase_server.py` 迁移为 Flask；保留 v0.1 `/health`、`/api/runs`、JSON events、resume 和 Evidence 语义；新增 Job/SSE。 |
| 领域关系 | ChatSession 独立；`job_id` 与 `run_id` 相同；内部 Run 状态映射为 CausalAgent Job 状态。 |
| 执行与持久化 | 单服务进程后台执行器；SQLite 和附件位于 `artifacts/showcase-v0.2/`，可通过环境变量覆盖；重启未完成任务进入 `NEEDS_REVIEW`。 |
| 工具 | `polynomial_check` 严格 schema；一次工具请求、一次 continuation、最多一次工具重试；`PythonMathTool` 仍为 experimental。 |
| 验证 | `verification_mode=auto|required|off`，默认 auto；候选检查和完整性分层；不适用返回 unknown。 |
| 题图 | PNG 延后 P1；P0 隐藏上传入口，兼容 API 返回明确 unavailable。 |
| 安全 | HttpOnly、SameSite=Lax、CSRF token；所有状态变更请求校验。 |
