# #173 B3 关联改题合同

基点 `408e33c`；父规格 #168。仅显式 Faithful 路径；正式澄清继续使用 #172 的专用回答入口。

- `POST /api/agent/jobs/<job_id>/revisions` 接收完整新题 `message`、原 `input_version` 和 UUID Idempotency-Key，沿用认证与 CSRF。主输入中的追加要求也作为完整新输入，不由服务猜测补全题意。
- 同一事务持久新题、独立 Job/Run 和双向来源，并停止原任务后续派发。原在途和 unknown 保留身份、预留及合法结算；迟到结果不能写入新任务或改变旧终态。重复动作返回原新任务，内容或版本冲突拒绝。
- 新任务使用独立预算、deadline、能力快照与证据，受现有工作线程容量及未决远端占用约束。未知结果零自动重发。
- 容量直接使用 `WorkspaceService.worker_capacity`，与创建线程池使用同一值（当前既有上限为 2），不另定改题阈值。已发出且仍 reserved/pending/unknown、无法证明结束的传输错误和未确认清理的工具占槽；已知拒绝、不曾发送及仅缺失 usage 不占槽。交付完成仍有未决请求的 Job 继续占槽。容量不足保持 queued，实际 worker 收尾后重查；unknown 不以过期或本地取消假装释放。Population 内部仍按既有独立容量合同执行。
- 浏览器主输入显示改题动作，与专用澄清回答区分；新旧任务可导航，刷新和重开只观察。

验证：复用公共 Job 受控 HTTP 失败场景，覆盖迟到/unknown 与幂等；聚焦前端浏览器、类型和构建检查。真实服务配置复用 #172 所指 #170 配置。全量最终门禁由父任务执行，未运行项记 not_run。继续使用当前选择的同一模型。
