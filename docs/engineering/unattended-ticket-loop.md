## 每个 session 的循环

1. 读取根 AGENTS、`docs/README.md`、当前任务合同和最近交接；核对工作树、HEAD、未提交改动、当前 GitHub 状态及前置依赖。保留 `tests/test.md` 原样，不读取。继续使用当前选择的同一模型；无法确认新 session 是否继承具体型号时记录未知，不猜测或主动换型。
2. 持有一个当前 ticket，持续完成实现、必要聚焦检查、审查、真实验收及文档。已验证且源码未变的证据直接复用；以真实公共入口闭环为主，不为内部角色或函数逐层补测试。实际失败先保留可执行见证，再做最小修复。最终工程门禁依工程门禁文档在退出时执行，失败只复查受影响部分，不无条件重跑整仓。
3. 若同一验收条件在两次有明确改动或诊断目的的尝试后仍无进展，先评估标准是否超出 ticket 的功能目标。用户已授权自主降低过高标准：可换更适合的代表题、取消额外成功次数/性能/大样本/双路线均完成要求、用已有针对性故障证据覆盖不必自然重演的边界。修改任务合同，记录旧要求、障碍、调整理由、替代证据和仍未覆盖的能力，然后继续，不无限重复模型调用。已失败记录保持原判，不追改为通过。
4. 完成当前票的可审阅退出条件后，提交并推送到当前集成分支，按 issue tracker 关闭该票。验收记录明确源码/配置、命令及 Run/Job/Attempt 和证据路径；局部能力不冒充 #168 整体完成。整理自己拥有的进程、临时检查和工作树，保留必要运行产物。
5. 重新读取 #168 及开放子票依赖，选一个已就绪的下一票。更新交接文件 `docs/engineering/unattended-ticket-handoff.md`，记录已完成票、下一票、HEAD、未提交工作、证据入口、进程/定时检查所有权及真实限制。
6. 使用 Codex `create_thread` 为同一项目建立一个本地新 session；任务提示明确当前票已完成、下一票编号、此合同与交接路径，以及“完成本票后继续此循环”。复用当前适用 checkout，不并发创建多个接班 session。记录返回的 threadId/hostId；确认其已启动或报告具体创建失败后，本 session 才交接停止。创建结果未知时先查询，不盲目重复创建。

## 调整验收的边界

正确答案、真实来源、官方 baseline 隔离、原根预算/deadline、权限、unknown 不自动重发、迟到不改写答案等仍按仓库合同执行。HTTP 成功、受控测试或错误答案不能标成真实解题成功；没有执行的项目记 `not_run`。#174 仍须有普通入口的自然并发真实回执和合格答案，不能用强制模式代替。#175 热切换单独验收。

长运行保持唯一后台实例，立即提供 PID、创建时间、阶段、完成计数和日志尾部的可执行监控命令，并使用每 30 分钟的临时定时检查；无变化静默，失败或完成才通知，完成后删除临时检查。交接转移现有监控所有权，不重复启动。

遇到缺少凭证、核心外部服务持续不可用或工具拒绝等无法由实现解决的阻碍时，记录真实状态和可恢复入口；不得为了维持循环伪造关闭票。平台中断或机器停止运行不能靠文档保证自动继续；下一次启动先核对既有 session 与进程后接续。#168 所有实施子票完成、用户取消或出现必须由用户处理的外部阻碍时结束循环。
