# Faithful 服务入口合同（2026-11-12）

起点：`1ca4fea64e72635b58b6720f32de3508be4d3527`。
用户授权后端闭环审计及补齐统一启动入口，随后明确目标为前端普通题目提交后由 Agent 按题目与进展自主选择已配置能力，简单题允许短路。统一配置仅是前置切片，不等于完整产品或能力验收。

## 要求与退出条件

- C1：既有命令无新增参数时保持原配置、默认 fake、legacy Job 默认值及官方 baseline。
- C2：`--faithful-config` 只接受本地版本化 JSON，显式要求 live；组装 Core 与 S01–S04/F1/F2 串行机制、表达、记忆管理、干预及系统视图。
- C3：容量策略、精确 Python 镜像及运行预算显式提供；不虚构容量或跳过运行时准入。并发使用独立预设和独立容量证据，不继承串行干预。
- C4：可选形式化只装配真实 Lean 执行器及既有策略；未配置时不伪造 backend，不授予 L3。
- C5：检查入口输出脱敏能力及输入要求，不启动 HTTP 监听或模型解题；配置错误和请求能力未就绪返回非零。
- C6：显式自动入口接受普通题目；规格生成必须通过同 Run 持久化模型调用及预算/unknown/恢复约束，再经结构与原题身份校验。不伪造笼统规格。已有人工规格及旧入口行为不变。
- C7：前端依据服务能力默认进入自主入口；未就绪明确阻止提交，不回落 legacy。高级模式仅作显式选择。简单题使用既有 Explore/整题核验短路。
- C8：分别核验能力已装配、Agent 可选择、执行可达及真实证据；并发、形式目标生成与同源干预的自主调度未验收前，不能宣称“完整自主架构”完成。

验证：先运行新增失败用例，再运行配置/公共 API 聚焦测试、相关回归与快速门禁，审阅 diff。真实 provider 全架构联调与数学效果独立记录为未验收。
