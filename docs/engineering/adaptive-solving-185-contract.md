# #185 按需求解合同

2026-11-15，增量策略 `adaptive-solving-v1`。官方 baseline 不变，旧 Run 不迁移。

## 策略

显式本地 `adaptive_solving: true` 启用；省略保持现状。策略随新 Run 配置身份冻结。
轻量起步不按文本长度、耗时或信心定数学难度。Explore 是现有完整候选生产者，
不另加难度分类调用。不能构造完整候选时走已有规划；多路线仍须当前容量和预算准入。
状态决策记录策略版本及封闭原因码，原 Job/Run、预算、截止和证据不重置。

第一次完整检查有具体 reason/counterexample 且无运行时资格拒绝或工具未满足时，
允许一次 Explore 局部修正，向其传递实际异议与草稿；每个新候选独立检查并绑定版本。
未知、协议失败、预算不足不触发数学修正。无具体异议或第二次拒绝进入 Planner。
澄清和用户指定验证仍执行；普通题不因新策略强制 Lean。

Planner 在已有请求中审查相关性、是否仅重述父目标、是否更难、求解路径及充分性；
这些是模型审查信号，不冒称机器证明。规划消费失败候选及异议，避免从头丢失反馈。
计量沿用共享 ledger，provider usage 缺失仍 unknown，预留不计真实费用。

串行 `search_context` 不包含调用身份、计数或时间；有效已证结果按内容去重，
工具输入不同即使输出相同也保留不同反馈。同计划的新动作继续使用原路线；
新计划才重新登记搜索前沿。它不改变 Population 的既有独立性准入，也不判断自然语言数学等价。

新 Run 同时冻结 `adaptive-search-v1`。停滞调度使用单独的 `no_feedback_rounds`：
新的实际工具反馈、有效已证引理或确证反例可允许同目标再次尝试；重复内容、心跳和
猜想改名不能刷新。当前 review 新产生的有效成果也在同一事务里参与搜索状态判断。
原 `no_evidence_rounds`、根义务状态及证明增益不因工具成功而增加或归零；搜索许可和
数学证明进度分开记录。规格重评保护及路线预算守卫优先于新反馈许可，旧 Run 不回填该策略。

完整响应的规格依赖若引用未声明目标，在 provider 接缝判为已知协议失败，
沿用一次 `:repair-1` 及原预算；准确的 normalizer 诊断随修复请求传递。
再次失败或 unknown 不自动续修。原规格校验、默认官方入口均不放宽。

显式高预算示例为 96 模型 / 96 HTTP / 24 工具 / 4194304 本地计账 token / 7200 秒。
这是对历史 48 / 48 / 8 / 2097152 / 3600 的多维扩容候选，不是 provider 容量承诺。
未配置 Population 或 formal 后端时仍报告能力限制；不能通过扩大额度绕过准入。
串行资源策略只在创建新 Run 时冻结，旧 Run 无该字段时不回填。直接 Explore 留一个
整题检查槽，Planner/Reasoner 等工作留最终生成和检查两个槽；尚未用过非 intake
协议修复时，再留一个共享修复槽。一次修复消耗该余量，不递归预留第二次修复。
模型/HTTP/本地 token 的余量在共享账本实际准入时再次检查；估算不写成真实消费。
既有 finalization 的原子双槽和 Population 预留继续独立负责各自阶段，不重复扣减。

时间份额复用当前适配器 timeout 与 retry 上界，工作阶段截止为原根截止减收尾份额，
并与已有阶段截止取最早值；不重置根时钟，不新增固定短超时。合法 YIELD 继续走已有
Planner/Reasoner 检查点；远端超过工作截止不能被假定取消成功，未知身份及预留保持。
工具次数、工具执行超时和 formal 环境继续走既有准入。后续上下文增长、额外工具或
第二次协议故障可能使估算不足；此时如实停止并保留成果，不承诺所有失败都能修复。
该估计和软截止的离线覆盖不等于真实长证明或所有阶段资源保障已验收。

Reasoner 检查点的工具请求和工具证据引用只能放在相应 `checkpoint.claims` 项，
不能直接挂在 checkpoint；已知 schema 错误的一次修复说明准确位置并保留原代码、
参数和数学主张。验证器才使用 verdict，Reasoner 不被要求填入不存在的 verdict 字段。

## 退出

必要离线反例覆盖直接检查、修正后新身份检查、无具体异议升级、第二次拒绝升级、
策略关闭及预算/unknown 边界；复用相关已有边界证据。少量真实普通输入覆盖简单、中等、
深度案例，记录源码、配置、调用与独立核对；未触发项保持未覆盖，不以离线通过代替。
最终双轴审查、一次冻结门禁；用户要求只做必要离线测试后，本轮只执行后端快速、
完整离线及发布检查，不安装前端依赖、不运行联网 audit、不追加真实模型调用。
这组三阶段检查单独标识，不冒称标准六阶段门禁。未满足的 #185 要求保持开放。
