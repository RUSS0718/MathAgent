# #97 非流式批次执行合同

状态：离线实现与发布门禁通过。2026-10-28 已按两个独立冻结登记执行真实批次。首批完成，但多步样本未进入登记要求的非快通道。r8 批次完成简单题后，多步题的第二次 Explore 请求超时，批次以 `unknown_transport` 停止并保留一个未决 attempt。两个 manifest 均已消费，不得续跑或重试。实际结果和仍未达成的条件见[就绪核对记录](../evals/star-readiness-97-status.md)。已确认[两题登记草案](../experiments/star-readiness-97-preregistration-draft.md)中的单 Run 与整批预算映射。任何新增真实调用都须使用新登记并取得针对该登记的授权。旧 RB08 注册、结果和执行器合同保持不变。

## 登记与身份

新批次使用独立版本和一次性归档目录。登记包含两题的题面、来源和精确 UTF-8 hash，按简单题、多步题顺序各派发至多一次；全部使用非流式。冻结 Intern S2、请求参数、完整 Reference 配置、源码 Git 版本、源码 hash、dirty 状态、单 Run 和全批硬限以及停止条件。通过独立 manifest hash 校验完整登记；缺字段、额外位置、篡改题面、提高预算、关闭审查、源码不一致或改变传输均拒绝启动。正式冻结的 manifest 必须在实现与离线验收结束后重新生成，因为测试或源码变化会改变身份。

## 执行和预算

协调器只为本地受信任操作提供入口，不向公共 HTTP 增加开关。它通过认证公共 Job 创建和收集同一 Job、Run、报告和 Evidence；只使用 loopback 的脚本 provider。S3 保持逐动作唯一账本，协调器检查批次剩余额度，不复制或重置单 Run 账本。启动环境预检只计入批次时间；每个 Run 通过预算准入后、派发前确定绝对截止，题目准入预检计入该 Run 时间，恢复保留原截止。全批 900 秒从服务启动前开始，包括预检和等待。每次派发前确认后续完整单 Run 预算及预检可容纳于剩余额度；不足立即停止。单 Run 和整批分别使用草案中已确认的 6/8/1/32768/300 与 12/16/3/65536/600，以及 2 Run、18/24/4/98304/900；环境预检最多 3 次，含预检工具最多 7 次。

不把缺失的 provider usage 当作零；保留预留并停止。网络未知不自动重发；完整但协议非法与传输未知分开。任何未知、失败、取消、硬限、身份或配置漂移、账本或绑定缺陷后停止新增派发；保留已发生 attempt 和证据。迟到结果只补记原 attempt 用量，不能覆盖终态。不得续跑、换题、提升额度或复用已存在的归档目录。

## 验收

通过真实本地 HTTP 替身、真实认证公共 Job、S3、S4、隔离工具和存储，分别验证简单题快通道、多步脚本路径及工具回执、审查与交付绑定。故障注入验证缺失用量、传输未知、协议失败、预算 / deadline、源码漂移和进程中断时不再派发；核查 tool / HTTP / token / Run / 预检和墙钟累计，确认不重复工具或模型动作。录入阶段、调用、回执和绑定的来源；未触发的机制记 `not_covered`。数学结果单列，内部 LLM 审查不等于数学证明。脚本结果不代表真实 provider 或能力提升。

登记、调度和最终来源的变更以失败用例先行，完成聚焦测试和同源码身份的离线门禁后再冻结正式登记。若实际运行所需单 Run 额度无法放入余量，停止并报告限制，不通过扩大预算来获得通过。任何新增真实执行仍需就具体登记和预算另行取得明确授权。
