## 交付目标

- ProblemSpec 保留原题要求、定义域、量词、假设、方向和输出要求，并有独立规格版本。
- Obligation 表示原题交付要求导出的根义务。辅助目标和引理只服务根义务，不能增加进度分母。
- WorkUnit 表示可调度动作，可以覆盖一个或多个根义务；合并或细拆工作块不改变原题义务数。AND 前提全部有效才允许依赖动作。
- 每项义务由与类型匹配、可追溯且经现有控制器接受的证据支持；例子、候选数值或模型自报不替代必要的普遍性、方向、可达性和完备性证据。
- 原题或约束变化产生新规格版本；受影响义务、辅助依赖、候选及现有证据引用失效并重核，无关分支保留。复用现有失效机制，不提前实现 S07 GraphBootstrap 或用图占位冒充验收。
- 根义务全部满足且实际收尾资源预留成功后，允许跳过非必要辅助工作，进入完整原题的独立整题审查；交叉检查假设、组合推导和实际交付文本。义务覆盖表不能替代 Whole Verifier 或 exact-text 绑定。
- 新 Run 显式启用并冻结版本化策略，默认关闭，旧 Run 维持原语义。复用 S02 容量治理并传播真实规格版本，保持原 deadline、共享预算、unknown 预留和调用身份。
- ProblemSpec 启用时，公开进度只投影 `root_obligations.covered`、`total` 和按原题顺序排列的 `items[{ordinal,type,status}]`；不公开义务 ID、义务文本、假设或证明内容。默认关闭和 legacy Run 保持原公开形状。

| 完成与收尾 | 根义务满足时不被非必要工作阻塞；未预留实际收尾资源时不冒称可完成审查 |
