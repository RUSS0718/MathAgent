# F8 真实试点接续规则

日期：2026-11-11。状态：frozen；版本 `faithful-f8-real-v1.1`。这是 [v1](faithful-f8-real-protocol-20261111.md) 的新执行版本，不修改 v1 合同、manifest、停止快照或首次结果。依据 [#157](https://github.com/RUSS0718/MathAgent/issues/157) 的实测归因循环：A 首题在 8 次正常 HTTP 后，审查模型用超出 Python 支持范围的 int(text,base) 生成计算并重复失败请求，触发既有安全拒绝；没有未知请求或产品缺陷。模型失误不得改成成功，也不应通过重跑挑选较好结果。

冻结审查：Standards（Fermat）和 Spec（Russell）均无阻塞，核对首槽原封存结果后允许冻结；未运行测试或请求。这是观察失败后制定的接续规则，合并报告必须明确事后修订，不能称全部按原 v1 预注册停止规则完成。该决定不代表执行 glue 或实验已验收。

## 不变的统计设计

保留原 14×7=98 个主槽身份、题集、参考答案、规格、源码内容、模型、prompt、预算、顺序、重复、工具、抽查和评分规则。A/B/C/G 共56主槽，加 D 的14主槽分别由原批次结果与新接续结果合并；原已派发失败槽仍用原首次结果，禁止接续再派发。E 原题 unsupported、F 条件专项、真实工具和真人未执行边界沿用 v1。数学 incorrect 或 unresolved 均不删除。

接续 manifest 绑定 v1 原 manifest/hash、新规则/hash、原源码 commit 与内容 hash、已封存结果 hash、原绝对 batch deadline、排除的所有已派发主键及剩余未派发顺序。实际产品源码及 applied config 不变。纯文档提交导致 revision 不同时，必须同时保存两个 revision 和相同源码内容 hash；报告明示这项差异，不靠相等 hash 隐藏配置变化。源码、配置、prompt、模型或预算真的变化仍另立不可比版本。

## 已知模型失败的处置与停止

只有同时满足下列条件的终态才能在记录归因后继续下一个原登记槽：

- Job 已终止为 failed/canceled，实际 error_code/phase 和公开报告封存。
- 所有已发送 provider attempt 为已知终态，模型身份未漂移；HTTP错误、断流、输出完整性不明不在此豁免内。
- 无 recovery unknown_calls/unknown_tools、protocol_failures、processing_failures；无本地持久化、账本、绑定缺陷。
- 工具回执全部有已知结果且清理确认；timeout、unknown_outcome、环境/隔离漂移不在此豁免内。模型代码产生的非零 exit 仅证明模型计算失败，不是数学反例。
- 停因由已封存 Solver verdict、重复/未满足工具请求、已知推理停滞或模型未能给出合格解构成；不能仅凭 failed 字样归为能力问题。每次按 #157 归因记录并保存机器分类依据；不修改求解器、禁用工具、提供参考答案或放松整题审查。

若归因材料不足，仍停批待诊断。任何真实请求未知、传输故障、模型漂移、工具未知/清理失败、源码漂移、预算违规、绑定或持久化缺陷继续硬停止，并公共取消所有活动 Job 后等待工作线程结束。缺 provider usage 继续 observe_only，不等同请求未知。

已知模型失败被保留后，下一题不重置旧槽 deadline/预留、不创建原题重试。接续只使用剩余槽各自既有上限及原批次剩余时间。每题可以失败，实验完整不等于求解全部成功；终态失败与 unknown 不会被实验批次状态“已完成”抹除。

## 条件任务和退出

若 C 未成功、未捕获可用记忆，G 仍按原空/暖 scope 和权限执行，实际记忆零条标 not_covered，不补造观察。F 继续逐题核验14个 C 的真实失败来源与暂停资格；有合格 checkpoint 必须冻结执行，终止失败后不能伪造新暂停点。暂停或未知尚未解决时不能算条件任务完成。

最终全登记报告逐槽引用首次结果，区分 completed/failed/unknown/incomplete/unsupported/not_run 与数学判决。接续仅在全部剩余必需槽有终态、条件任务按合同执行或证实不适用、28槽独立辅助审查及解释rubric完成、完整性/来源链和双轴审查通过后退出；必需槽尚未启动或未知阻塞未处置，#157保持开放。工程门禁仍只因产品代码修改而重跑；本次规则调整不产生模型能力提升结论。
