## 目标与范围

用户能从关键进展或星图查看某个角色实际保存了什么：采用的方法、必要公式、阶段结论和未解决点。页面必须区分候选与检查通过，并说明检查范围。角色状态实时更新；数学摘要只随已保存阶段成果更新。点击、展开和重试读取均不生成新成果。

本轮只设计桌面右侧详情面板。手机界面和手机测试不在范围内，不引入新的手机交互方案。沿用现有任务、权限和求解流程，不改变官方 baseline、模型预算、调度或最终答复规则。面板不承担教学改写、报告生成或触发角色参与的职责。

普通页可以展示获准公开的结构化数学结论；完整 prompt、模型内部推理草稿、私密工作记录和模型报告正文不得直接搬入普通页。已有报告访问权限不自动扩大到角色面板。

关联边界见[解题页界面合同](../engineering/user-solving-ui-contract.md)、[工作台集成合同](../engineering/conversation-workbench-contract.md)及[失败展示修复记录](failure-state-fix.md)。本文细化角色成果展示，不借用其他功能的验收结果。

## 页面与详情层级

### 主页面与两个入口

关键进展每条保留一句成果摘要；无获准成果时给出准确的状态短句，不伪造方法或结论。阶段状态和成果摘要分别投影，避免状态文字覆盖已保存的数学摘要。

点击关键进展中的角色名称打开同一个右侧角色详情面板，定位该条对应的角色、成果和来源版本。点击星图节点打开相同面板，默认显示该角色当前有效成果。大小星图使用同一规则。打开面板不改变角色或步骤筛选；仅**只看该角色**操作改变角色筛选。

两入口定位同一任务、角色、成果版本时，正文、公式、检查范围和有效性必须一致；定位不同历史版本时允许内容不同，但必须标明版本，不能用当前内容填补历史。节点名称、状态、阶段和可读版本号可以显示；原始 `call_id`、hash、事件 ID 等技术身份不作为产品标签。

### 面板内容

面板依次呈现以下信息：

1. 角色名称、职责、当前运行状态，以及当前阅读的阶段和版本。来源不明时明确标注。
2. 成果列表。默认最多展开三条成果，其余通过**更多成果**按需展开；不足三条不补齐。这里限制的是默认展开条数，不保证长公式在一个物理屏幕内全部容纳。
3. 按职责呈现实际保存的方法、必要公式、阶段结论和未解决点，并分别显示有效性和检查范围。不要求每个角色填满四个栏目；关键内容缺失时合并为简短的“未记录”或“未公开”说明，不堆叠空栏。不从角色职责推断内容；有记录的“无未解决点”才能显示为无。
4. 历史成果、**查看当前成果**和**只看该角色**等次级操作，以及明确的关闭按钮。已失效成果只在历史语境中展示，不混入当前有效成果列表。

首版按保存顺序呈现成果，默认展开最近三条；历史事件入口优先展开被选中的对应成果。不得用展示排序推断数学重要性。必要公式指所选成果公开陈述中支撑该结论的公式及适用条件：摘录保留完整数学单元，不用省略号截断公式、量词、定义域或成立条件。来源缺少方法或公式时直接说明，不自动补写。

以下是**虚拟界面示例，不是实际求解或能力证据**：

> 主页面：推理 · 步骤一提交了非负性结论，等待步骤检查。
>
> 详情：推理／步骤一／计划第 1 版；方法：平方非负；公式：对任意实数 \(x\)，\((x-1)^2\geq 0\)；阶段结论：取得下界候选；未解决点：尚待核对原题的取等条件。
>
> 有效性：当前版本；检查范围：候选，未检查。

只有保存来源确实含有上述内容时才能这样展示。相同公式即使已通过步骤模型检查，也只能标记该步骤的实际检查范围，不能据此宣布整题已证。

### 阅读稳定与异常状态

阅读期间保持角色、所选成果版本、已展开内容和滚动位置。新成果到来仅提示**有新成果，更新查看**；用户主动更新后才切换正文。再次打开相同阅读上下文时恢复所读位置；切换任务不能继承其他任务的正文或缓存。

正文冻结不冻结有效性。新计划或依赖撤销使当前所读成果失效时，及时更新为**已替换**或**已失效**，移除“当前有效”的绿色标识，但不自动切到新正文或改变滚动。仍成立的成果以权威有效性判定为准，不因新计划出现就全部判失效。

所有角色都可点击。未参与时显示职责和“未参与”；参与中但尚未保存成果时显示运行状态与“尚无已保存成果”；已有结果但未获准公开时说明“成果内容未公开”。这些状态不能混用。查看未参与角色不会使其参与。

加载时显示读取状态，不用空态提前断言没有成果。API 读取失败只提供**重试读取**；不得改成“暂无成果”，也不得发起求解。可以保留已读内容，但必须注明**最新状态未确认**，不能继续以未经确认的绿色徽标宣称当前有效。

任务整体失败、取消或处于结果未知的运行语义时，不抹去此前仍有效的阶段成果。沿用既有 Job 状态枚举，结果未知不能据此新增 Job 终态。面板同时说明任务终态和成果边界；已失效内容仅作历史。任何查看操作都不自动重跑、恢复、重发或补生成。

## 有效性与检查范围

每条成果的两类标识独立：

- **有效性**：当前版本有效、历史版本、已替换、已失效，或最新状态未确认。由权威来源及依赖判定，不由组件的缓存时间或任务是否成功判定。
- **检查范围**：计划、探索候选、待检查、步骤模型检查、工具检查、整题模型审查，以及未通过或结论未知。标签同时指出检查对象与适用范围；多种检查可并列，不合成一个无范围的“已证明”。

保留原始分类与证据等级的含义。工具回执只能支持其实际计算或形式目标；数值抽查不能证明普遍命题，形式工具也不能把局部目标扩大为整题。步骤模型接受不能自动转成整题审查通过。候选被采用、终稿生成成功、任务结束和计划结构通过都不构成证据升级。显示当前有效的候选，也必须同时显示“候选，未检查”等准确等级。

## 数据与来源引用合同

本文规定引用原理，不冻结 endpoint、路径、存储表或完整 schema。实施前先审阅最小公共投影及旧数据行为，再由生产者和消费者共用同一来源语义。

新阶段成果在正常求解的保存边界留存稳定来源引用。引用需能确定所属任务和 Run、角色、题目规格与计划或尝试版本、对应步骤或阶段、成果记录及正文版本、所关联的检查记录和范围。适用维度缺失时不能伪称来源完整。正文和检查绑定到同一成果版本，不能仅靠角色名、步骤序号、时间接近或“最新快照”关联。并非要求所有原始技术身份进入公共 DTO。

查询根据来源读取已保存内容；固定模板从允许公开的结构化字段确定性投影，不新建成果、不补写历史引用、不延长 deadline。有效性变化可关联到旧正文，使正文保持可读而状态及时失效。公共响应只包含必要的可读内容和经授权的定位引用；服务端逐次验证任务归属及权限，不能依赖前端隐藏链接。

旧数据只有在现存来源足以确认时才正常展示。历史事件没有可确认的正文版本时，显示**该条历史成果无法还原**，可以保留原事件的安全状态摘要；不得将当前成果当成当时成果。**查看当前成果**由用户明确触发，并清楚改为当前语境。不能为兼容旧数据回填引用、重跑任务或补一次模型生成。来源冲突或损坏也不能回退到另一个任务的同名成果。

只读指查看不改变 Job、计划、成果、审查、预算、deadline，以及模型、工具和供应商 HTTP 请求的派发计数与身份。允许读取已保存数据的 HTTP 请求；禁止以读取为由派发新的模型或工具请求。既有鉴权会话维护单独计量，不要求全库字节不变，也不允许借此豁免数学业务写入。

只读验收使用冻结数据夹具，或按来源审计区分“查看请求”与“后台原有求解”。后台新成果独立到来不是查看写入；验收必须能归因，而不是简单比较两个时刻的总数。切换任务后的迟到响应必须丢弃，缓存也必须包含任务和成果版本边界。

## 编号验收标准

下表是待实施的可执行场景，不预记测试通过。夹具、截图和计数仅作为展示、来源与只读合同证据，不证明数学能力提升。可合并场景取证，不要求每个编号新建测试文件。

| 编号 | 可执行场景 | 可观察结果 | 失败判定与证据 |
| --- | --- | --- | --- |
| RS-01 | 为同一任务、角色和成果版本配置关键进展与星图入口，依次打开并定位同一成果 | 使用同一面板，正文、公式、版本、有效性和检查范围一致；星图首次打开默认当前有效成果 | 任一内容或等级不一致即失败；保留来源夹具、双入口截图或 DOM 断言 |
| RS-02 | 保持已有角色与步骤筛选，点击大小星图节点和关键进展，再单独操作“只看该角色” | 前两种点击只开详情；独立筛选操作才改变角色筛选 | 点击隐式筛选或清空步骤即失败；记录操作前后筛选值及可见列表 |
| RS-03 | 同一角色保存旧成果 A 和新成果 B，点击 A 的历史事件 | 显示 A 的正文与版本，标明历史语境；B 不冒充 A | 出现 B 正文、旧检查附着新正文即失败；引用映射与画面共同取证 |
| RS-04 | 准备缺历史引用的旧事件，再选择“查看当前成果” | 先明确无法还原；主动切换后显示当前语境；无当前成果则准确说明 | 默认填入最新内容、回填或重跑即失败；保留两步界面及写入、派发记录 |
| RS-05 | 打开任务甲详情后切至任务乙，让甲读取响应迟到；另尝试以甲引用读取乙的内容 | 迟到响应不污染乙；服务端拒绝不匹配引用，缓存不串任务 | 跨任务显示或返回受限内容即失败；请求响应与任务绑定记录取证 |
| RS-06 | 在冻结业务夹具上重复打开、关闭、展开、切历史及刷新读取 | Job、计划、成果、审查、预算、deadline 和模型工具计数、调用身份均不变；不新增供应商 HTTP 派发 | 任一查看引起业务写入或派发即失败；对比业务快照与调用审计，鉴权维护单列，不比较全库字节 |
| RS-07 | 用受控事件模拟后台原有求解，并在查看期间保存一条已安排的后台成果；无需实际模型调用 | 新增状态与调用记录可归因到原求解，查看没有独立写入或派发 | 无来源区分而判定只读通过，或把后台写入算作查看写入，均属证据不足；保留请求关联审计 |
| RS-08 | 依次放入计划结构通过、探索 worked、猜想、已采用候选及终稿已生成记录 | 分别保留计划或候选等级；不出现证明或整题通过标记 | 等级被展示逻辑升级即失败；使用同组投影输入输出断言 |
| RS-09 | 配置步骤模型接受、有限工具抽查、局部形式目标及整题模型接受，并为另一候选保留旧审查 | 各自显示检查对象与范围；另一候选不继承通过 | 数值抽查泛化、局部冒认整题或跨候选复用标记即失败；保留回执、候选绑定与界面断言 |
| RS-10 | 点击九个角色中未参与的节点，另为参与中角色配置尚无成果状态 | 均可打开，职责准确，分别显示未参与或尚无已保存成果；不触发参与 | 不可点击、虚构摘要或新派发即失败；角色清单、画面及调用计数取证 |
| RS-11 | 延迟首次读取，随后返回真实空成果或内容未公开的响应 | 先显示加载；成功后区分没有成果与未公开 | 加载时提前显示空态、把未公开当未参与即失败；保留分阶段响应与界面 |
| RS-12 | 首次读取失败，再在已有正文时使状态读取失败，然后点击重试 | 仅重试读取；保留正文时标注最新状态未确认，成功后按实际结果恢复 | 假装没成果、保留无条件有效徽标或发起求解即失败；请求方法、目标和派发计数取证 |
| RS-13 | 为失败任务、取消任务及结果未知的运行情形各保留有效阶段成果和失效成果，不新增 Job 枚举 | 任务状态及运行语义准确；有效成果仍可读，失效成果只属历史；无自动重跑 | 全部抹除、混作当前有效或自动恢复即失败；快照、画面和零新增派发记录取证 |
| RS-14 | 阅读旧版本并滚动、展开；推送同角色新成果，再主动更新 | 推送只提示，原正文、版本、展开与滚动保持；主动更新才切换 | 自动替换正文、跳滚动或切角色即失败；交互前后定位与滚动值取证 |
| RS-15 | 阅读时由新计划撤销当前成果或依赖；另保留一条确认仍有效成果 | 失效标识及时更新，旧正文和滚动保留，不自动切到新正文；仍有效项不误失效 | 冻结绿色有效徽标、自动换正文或一律撤销即失败；撤销事件、权威状态与画面取证 |
| RS-16 | 同一任务关闭后重开相同阅读上下文，再切至另一任务 | 前者恢复所选角色、版本、展开和滚动；后者不沿用前者正文 | 重开丢失阅读位置或跨任务串内容即失败；操作序列与界面状态取证 |
| RS-17 | 准备含长公式、条件、四条以上成果和缺方法字段的记录 | 默认最多三条展开，更多按需打开；完整呈现必要公式与条件，缺项明确说明 | 公式省略截断、擅补方法或默认全展开即失败；桌面截图和源陈述对照 |
| RS-18 | 更新运行状态但不提交新成果，再提交一条保存成果 | 状态及时变化，摘要在无新保存成果时不被状态文案覆盖，提交后可提示更新 | 用状态替换数学摘要或展示未保存草稿即失败；投影序列与 DOM 对照 |
| RS-19 | 未授权用户直接读取定位引用；授权普通用户读取含敏感内容的来源 | 前者被服务端拒绝；后者只得允许字段，无凭证、个人信息、完整 prompt、私密草稿或模型报告正文 | 仅隐藏入口、原文泄露或越权返回即失败；受限响应断言与脱敏样本取证，不保存真实秘密 |
| RS-20 | 正常打开面板并检查标签、提示和无成果角色 | 仅显示角色、阶段、可读版本及准确状态；无原始 call_id、hash 等身份；无产物不编摘要 | 技术身份进入产品标签或职责被当作成果即失败；DOM 文本与公开响应检查取证 |
| RS-21 | 使用 Tab、Enter、Space 从两个入口打开，操作更多和筛选，按 Escape 或关闭按钮返回 | 控件有可见焦点与可理解名称；打开后焦点进入面板，键盘可到达操作，关闭返回触发点；触发点消失时返回对应区域稳定控件 | 焦点丢失、无法退出、键盘不可用或读屏不能识别面板标题即失败；桌面键盘轨迹与焦点断言取证 |
| RS-22 | 对来源引用缺失、损坏、版本冲突分别读取；尝试多次重试 | 明确来源不可确认或读取失败，不改读最新或其他任务，不写入修复、不补模型调用 | 静默回退或借读取修复数据即失败；响应、审计与原快照对照 |

## 后续实施分层与定向验证

以下是后续实施切片，不代表本轮已开发。实现时按[仓库规则](../../AGENTS.md)保留可复现的先失败案例，再做最小修改。验收结果另记实际源码版本、工作树差异、命令和证据位置，不在本文预填成功。

| 层次 | 最小交付 | 定向验证与退出条件 |
| --- | --- | --- |
| 数据来源与公开投影 | 审阅稳定引用、有效性和检查绑定的最小合同；为新保存成果保留所需引用；定义旧记录不可还原响应与白名单 | 聚焦 RS-03–09、RS-19、RS-22。证明同版本与任务隔离、只读和公开边界；无需真实模型生成新样本 |
| 共享展示投影 | 两入口共用成果解析，状态与正文分离；别名归并、缺项和检查范围按表呈现 | 用少量固定夹具覆盖 RS-01、RS-08–13、RS-18、RS-20；不为每个标签重复造同构测试 |
| 桌面面板与交互 | 连接入口，拆分筛选操作，限制默认展开，保留阅读上下文并单独更新失效标记 | 少量合并的桌面浏览器场景覆盖 RS-01–05、RS-10–17、RS-21；检查代表性长公式、失败状态和键盘路径，不新增手机方案或测试 |
| 集成复核 | 核对上述契约及本次实际变更的受影响回归，审阅最终差异 | 优先复用现有相关测试；必要时只读复查可访问的已保存任务，不新建求解。缺证据逐项列为未验证，不以结构检查替代能力结论 |

本功能不要求为了验收重复运行完整离线门禁、大样本评测或真实模型与工具调用；验证范围以实际受影响合同为限。如发现需要改变调度、预算、官方路径或扩展公开私密正文，超出本文范围，先重新审阅设计。

实施前需重点讨论的风险是公共投影白名单不足、旧事件无法绑定历史正文、有效性更新与阅读冻结的竞态，以及公式缺少专用字段。首版以准确缺省和保真摘录收口，不以新增生成、猜测来源或等级升级消除这些缺口。
