# MathAgent 实验开发计划书

日期：2026-10-21。目标仓库：RUSS0718/MathAgent。检查基线：develop 的 5b0e1912e1cc82d7ab1ecd3bcb8ea5ffc10933ae。环境设置分支：chore/experiment-setup-intern-s2。

## 一 目标与执行原则

本计划先服务比赛主观评测的完整交付，再从真实有效的系统机制中形成学术贡献。依据仓库 AGENTS.md，客观正确性占 60%，主观评测占 40%；主观部分包括推理策略与系统设计 10 分、展示质量 20 分、创新性与可扩展性 10 分。该映射用于安排工作，不能据此承诺得分。根 user_agent.py、implementations/、requirements.txt 和 BASELINE.json 所描述的官方行为继续保持冻结。

五个研究方向都采用可关闭组件，统一使用 Intern S2 API。先建立可以计量、停止、回放和审计的实验底座；再按 R1、R2、R3、R4、R5 的可行性顺序验证假设。R3–R5 的基础工程能力可以提前建设，形式化与理论扩展不作为比赛演示的前置条件。只深入一到两个通过筛查的方向，其他方向按证据保留、降级或归档。

本轮交付是计划、各方向开发前文档、离线设置及验收记录。新研究算法、在线预算控制器、真实 API 探测、数学性能实验和远端 PR 按后续切片执行；设计文件存在不代表功能已实现。所有建议阈值均是待冻结的实验合同，不是已经得到的实验结果。

### 三种独立的晋升结论

| 结论 | 判定依据 | 后续动作 |
| --- | --- | --- |
| 工程保留 | 公开接口正确、可关闭、可回退、可观察，有明确系统用途 | PR 到 develop，研究组件默认关闭 |
| Showcase 配置启用 | 在目标工作负载上通过质量、成本、故障与展示验收 | 单独的启用 PR，保留一键回退 |
| 学术深入 | 强基线、独立数据、机制证据及统计精度支持贡献 | 扩大实验、复核近邻、撰写论文 |

一个学习路由器没有超越简单规则时，可以保留动作接口、计量和简单规则。普通缓存效果好时可以保留缓存，同时停止声称提出新的证明恢复算法。工程保留不要求每个组件单独构成论文创新。任何组件进入官方路径，都需要另一次明确的官方发布决策与验收。

## 二 develop 的现状与 setup 的优先级

现有代码已具备 Flask/Vue Workbench、公开 Job/Run 接口、SSE、本地持久化、工具 Registry、限定域 polynomial_check、Evidence 与回放、Intern 客户端和离线检查。继续复用这些接口，不另起一套 Agent 平台。旧 LangGraph 执行循环与当前 live workspace 的 LiveAgentPipeline 是两条不同路径；旧路径的 checkpoint 能力不能直接当作 live 路径的恢复证据。

当前应优先解决以下问题。依据是本次源代码检查，完整观察与定位见 develop-inspection.md；它们是修复任务，不是本轮已经完成的修复。

| 优先级 | 观察到的缺口 | 实验与展示影响 | 最小切片 |
| --- | --- | --- | --- |
| P0 | 客户端 chat 返回文本，Adapter 常得到空 usage；缺失量可能被记为 0 | 成本比较失真 | 传递脱敏请求诊断，缺失值为 null，明确计量来源 |

先合入公共底座，再从同一个 develop 基线建立五个方向的工作分支。当前先完成 setup 分支，不预先制造五个“实验已完成”分支或空 PR。各方向可使用独立 git worktree；不同任务不得同时修改同一个工作树。若某方向依赖尚未合并的接口，明确记录依赖，优先把最小公共接口独立合并；不能偷偷依赖另一个分支的未提交文件。

每个方向的 PR 面向 develop，包含机制实现或有用基础能力、实验结论和证据索引。负结果也归档：有用代码可以合并；无保留价值的算法保持关闭或删除，保留脱敏结论和复现协议。最终 PR 不等同于自动合并，更不等同于进入 main。

研究分支在归档点保留不可变提交，并可加带注释的 archive-r1-v1 等标签。分支删除与否不决定证据是否存在；归档记录绑定提交、配置和外部证据哈希。后续 develop 变化时，保留原对照工作树；新版本比较单独成组，禁止混合不同基线的结果。

## 四 按 Matt Pocock skills 组织开发

本轮查阅的上游版本为 mattpocock/skills 的 5beb35b040e3de97e54fa9e386d7e42d15c295c2。当前名称为 to-spec、to-tickets、implement、tdd、code-review、pr、retro。用户要求的 PRD 在本项目继续单独保存，并和技术规格互相引用；不因上游改名而取消 PRD。

沿用仓库已有的 GitHub Issues、五个状态标签、GLOSSARY 与 ADR 约定。to-spec 将已确定的需求写成规格；to-tickets 将规格拆成可独立验证的纵向切片，显式列出阻塞关系。每个开发切片先有可审查的验收合同，然后进行一次失败验收、最小实现、针对性检查、相关完整回归、审查和逻辑提交。文档和纯配置不制造只复述实现的测试。

| 阶段 | 必须留下的产物 | 退出条件 |
| --- | --- | --- |
| 产品目标与调研 | PRD、比赛评分映射、近邻与差异说明 | 使用者、用途、非目标和成功条件清楚 |
| 风险验证 | 一个高风险问题的 spike 记录 | 真实协议或确定性行为可复现；失败则收缩设计 |
| 技术设计 | ADR、技术文档、结果类型与成本合同 | 关键取舍可解释，复用边界明确 |
| 规格与切片 | spec、tickets、依赖图、验收案例 | 每个 ticket 有独立可验证的用户行为 |
| 开发 | 短分支、纵向切片、TDD 记录 | 公开接口符合合同，新增行为可以关闭 |
| 实验与回归 | 预注册配置、指标、失败摘要 | 数据有效性先通过，再判断收益 |
| 展示加固 | 故障演示、脱敏 Evidence、live/replay 标记 | 评委能理解发生了什么，异常不变成空白成功 |
| 审查与 PR | Standards 与 Spec 两条审查结果、PR 说明 | 已解决阻塞问题，证据与主张一致 |
| 复盘 | 导航、自动检查、环境改善记录 | 下次运行不重复踩同一环境问题 |

测试优先使用已有的 Adapter 公共接口、Job HTTP/SSE/报告合同和工具 invoke 边界。它们能验证可观察行为，不能证明模型数学能力。新的实验 CLI 只检查离线配置、基线与文档合同；不会用 mock 结果证明 live 功能。

PR 描述沿用 pr skill 的 Summary、Evidence、Merge Danger：展示最小必要的流程或差异、修复前后证据、可逆性与影响范围。实验附加基线、预算、指标、否定结果、默认开关与证据链接。Issues 与 PR 的 ID 只能在实际创建后填写，不能预造编号。

### 环境与复现

Python 采用仓库固定版本与 uv.lock，使用 uv sync --locked --all-groups。仓库检查采用 uv run python scripts/check.py --offline，发布检查采用 uv run python scripts/check_showcase_release.py。前端使用仓库锁文件与既有 CI 指定的 Node 版本，依次运行 npm ci --no-audit --no-fund、npm audit --audit-level=high、npm run check。

Lean 不进入官方依赖，只有 R3/R4 的形式化子实验需要；首次启用时固定 Lean、mathlib 和编译环境版本。确定性数学工具复用受限 schema，不把任意 Python 执行当作已完成的安全沙箱。

历史官方 88/12/0 记录只是该历史评测事实，不作为本次 Intern S2 新实验的正确率。每个算法对照必须运行在相同数据、相同实际 API 模型、同一计量方法和总资源约束下。相同 max_tokens 不等于相同总推理预算。

数据分四部分：D-smoke 是公开或人工构造的小规模工程案例；D-dev 用于调试和动作采集；D-cal 用于阈值与预算选择；D-test 冻结后只用于确认。按原始问题或题族分组，同题不同前缀、翻译、改写和重复运行不能跨集合。记录公开来源、版本、许可证、内容哈希及去重规则；测试标准答案不进入求解上下文。

数学效果先采用公开文本题，覆盖工具适用、工具域外、多步推理、无完整输出等情形。题集选择可从 MATH500、GSM8K 及适合比赛风格的公开题中分层抽样；正式题量按试跑方差决定，不能将小规模演示题同时充当盲测集。AIME 等小样本可作外部压力测试，不能单独支撑稳定的百分比收益。公开基准可能被模型训练见过，该限制写入论文。

原始题、答案、模型原始输出留在被忽略的 artifacts 或指定证据存储；Git 保存协议、版本、哈希、脱敏汇总及代码。合成故障只验证工程行为，其结果与自然发生的数学错误分别报告。

## 七 Intern S2 与预算策略

正式服务模型固定为 intern-s2；不使用动态别名 intern-latest。官方服务文档列出 256K 上下文、默认 thinking_mode 开启，并建议工具密集场景保留 thinking。Chat 接口默认 30 请求每分钟，文档说明 120 秒未完成会返回截断结果；tools 请求不支持 stream。这些是服务文档口径，具体账号能力仍须短探测核验。资料与探测步骤见 intern-s2-api-contract.md。

所有 Planner、Solver、Verifier、Formalizer 和 Prover 的模型调用均使用同一 Intern S2。确定性 CAS/Lean 可以作为工具。不同角色提示不称作不同能力模型；缺少 seed、logprobs 或推理强度参数时不虚构。可见前缀再调用不代表恢复隐藏思考状态。模型仍可能在同一个服务 ID 下更新，记录返回型号、ref_model、时间窗口与哨兵样本，不承诺位级可重复。

### 无需预估总预算的启动办法

以下数字是保守的起始调度上限，实际运行前写入配置；不是单价、总费用或数学成功率承诺。没有凭证与明确阶段配置时只运行 offline。首次探测和计量结果出来后，在已设总额度内调整下一批题量，而不是一次性启动五个完整实验。

| 阶段 | 数量设计 | 调度上限与目的 |
| --- | --- | --- |
| G0 离线设置 | 文档、配置、mock、基线与故障合同 | 0 次推理请求 |
| G1 API 短探测 | 1 次 models 查询，最多 8 次短生成 | 单请求在途，max_tokens 不超过 512，自动重试为 0；确认结构和能力，不评估数学 |
| G2 成本与闭环试跑 | 12 道开发题乘以两策略得到 24 个 Run；其中 3 道工具题每策略各追加 1 次，共 30 个配对 Run | 全批最多 128 次生成 HTTP attempts；每 Run 最多 4 次逻辑调用；每次 max_tokens 不超过 8192；初始总输出预留不超过 16384/Run |
| G3 方向筛查 | 每方向先 24–40 道开发题，约 1 个可见前缀/题，3 动作；先 1 次续写，有差异再补独立重复 | 最多深入 1–2 个方向；题量与 request 上限由 G2 的 p50/p90 成本推算 |
| G4 冻结确认 | 通常从 200 道独立问题规划，按方差与目标效应扩至 500 或更多 | 先冻结策略、主要指标、题量与查看次数；预算不足则缩小主张 |
| G5 论文扩展 | 新题型、预算迁移、机制检验及必要形式化 | 仅对通过 G4 的方向追加 |

G1 的 8×512 只是生成额度之和，不是整批总计费 token。G2 的重试包含在 128 次总 attempts 内；单次重试必须再次申请额度。建议初始实验串行、全局限流设为不高于 20 RPM；短探测稳定后才考虑 2 个在途请求。该并发值是本项目初始配置，不是提供方承诺。

G2 初始设置 100 万“已计量加预留的总 token”调度阈值与 2 小时批次活动期限；单题最多 600 秒。仅当实际 usage 口径已验证时，token 阈值才可用于对应计量口径。usage 缺失时保留 missing/estimate 标记，不伪装为真实硬上限，依靠请求数、输出参数和时间停止新增调用。隐藏思考、超时在途计费或未知服务开销不能由本地 max_tokens 保证；金额上限须依靠已确认的账号额度或服务方设置。

G2 必须检查“短预算造成的截断”。若多数答案在当前上限下无法完成，先缩小题数、比较更长首次生成，重新冻结预算档位；不将为截断补全的收益当作 R1/R2 创新。

### 成本账本

维护三个口径：项目总消耗包括所有候选动作、标注、校准和失败；部署消耗只包括该策略实际选择的路径；确定性工具消耗单列执行、编译与存储时间。一个动作价值样本为研究生成了三条路径，不能把三条都算成部署成本，也不能从项目总消耗中删除。

每个 HTTP attempt 在发出前原子预留请求数、输入估计和输出上限；返回后以真实 usage 结算。记录 requested_model、returned_model、request_id、run_id、action、attempt、thinking_mode、max_tokens、finish_reason、input/output/total、usage_source、耗时与停止类别。缺失量用 null。提供方 total 已包含的 reasoning/cached 子项不重复相加。并发 worker、恢复和重试共用同一账本。

超时请求不能自动认定未计费，也不能将其预留立即释放给新调用。保留 unresolved 状态直到账户或请求状态可核对；若无法核对则保守占用。客户端取消只停止新调度与接收，不声称撤销服务端计算。

取得价格后，用实际计量的输入、输出及适用费率计算费用；价格未知时金额保持 null。先报告每题 p50/p90 请求数、输入输出 tokens、端到端时长、失败率，再给下一批成本区间。预算分配优先预留最终确认和展示加固资源，不五等分：建议可用新增额度的 25% 留给独立确认、20% 留给回归/展示/异常；其余由筛查结果分配。比例可调整，最终确认份额不能被开发反复调参耗尽。

## 八 五个研究方向的实施与判定

### R1 同模型局部动作收益路由

组合局部错误信号、工具适用性与动作净收益。动作先限于沿可见前缀继续、同一 S2 局部重推、适用 CAS 检查后受限修复。控制器只看动作发生前的可见信息；执行结果与未来影响只能作为训练标签。先做规则版，再用少量配对数据训练轻量控制器，不先训练 Solver 或引入在线 RL。

核心对照是最强简单规则、固定动作、随机动作和更长首次生成。所有动作共享剩余预算，成本包含前缀重发、计划抽取、工具调用与答案收束。主要指标是固定总成本下的正确率、错转对减对转错的净修复率、失败率、工具覆盖率与 p90 时延。

进入深入的条件是动作确有可预测差异，且在未见题上超过 B-rule；如果规则更好就保留规则和接口。只有答案截断补全有效时，归档为完成状态与预算工程。详细 PRD、技术文档和 ADR 分别见 docs/prd/research-r1-prd.md、docs/specs/research-r1-technical-spec.md、docs/adr/0008-r1-same-model-actions.md。

### R2 DE 反事实动作控制

比较同一可见前缀下的继续轨迹、保持计划重新执行、更换核心计划。计划必须来自当前可见上下文；用结构化计划签名与小规模独立人工审阅检查干预确实保持或改变策略。不把 S2 自评当真值，不把不能判断的样本强行分成 Discovery 或 Execution。

最关键基线是相同动作集合与相同采集数据下的直接 Q(prefix, action) 控制器。还需固定 continue/restart、预算匹配多次尝试、仅长度/预算控制器。用一组续写估计动作排序，另一组独立续写评价排序，避免在同一候选池内挑最优后自评。

若 DE 表示没有超过直接 Q，就保留可用控制器，停止“发现状态识别”的核心主张。若干预混同，先修定义再采集。优先把 R2 作为主论文候选，但不提前承诺投稿或性能。对应文档为 research-r2-prd.md、research-r2-technical-spec.md、ADR-0009。

### R3 UNKNOWN 分诊与预算分配

工程版本先把适用域外、schema/解析失败、工具超时、前提不足、已验证、已反证、未验证和主动跳过明确区分。UNKNOWN 不是数学错误。限定域 polynomial_check 的候选有效也不是完整解集证明。

研究版本从可信原生形式命题开始，比较给翻译、证明、补充可信依赖或返回重推分配预算。所有模型仍用 S2，Lean 固定版本；自然语言到 Lean 只在必要性与语义忠实度可证明后加入。核心基线为固定预算、按错误码规则、只加翻译、只加证明和平均分配。

只有可信证书率或端到端正确性改善且成本有收益才深入。若学习分诊不胜错误码规则，保留规则；若 S2 的形式能力不足，缩小范围，不让 Lean 阻塞演示。对应文档为 research-r3-prd.md、research-r3-technical-spec.md、ADR-0010。

### R4 带假设作用域的证据复用

先缓存确定性工具结果，缓存身份包含规范化输入、定义域、假设、实际依赖及工具环境版本。改前提、改定义域、改环境时使相关证据失效；保守依赖集优于不可靠的最小依赖。跨测试题默认不共享生成记忆，避免前后题信息泄漏。

只有取得真实 Lean 证明对象后，才把功能称为子证明复用。研究比较无缓存、同样正确键规则的普通缓存、依赖闭包失效、全重启和预算感知恢复；把依赖提取、重验、编译和存储成本都计入。

没有真实复用频率就关闭缓存；普通缓存已经最好就保留普通缓存。不能只用人工随机 DAG 证明数学 Agent 有效。对应文档为 research-r4-prd.md、research-r4-technical-spec.md、ADR-0011。

### R5 最终接受风险审计

工程版本为最终交付对象建立唯一身份，区分“答案已返回”“候选经过某工具验证”“完整命题有形式证据”。接受、拒绝、待复核与覆盖率分别记录。综合器改写内容后必须重新绑定验证，不能沿用旧候选的通过结论。

学术版本先冻结一个策略，在独立校准集上研究最终被接受对象的条件错误风险；再考虑自适应搜索与恢复。标签优先来自可执行的精确判定、可信形式输入与 kernel 或独立人工审查；S2 自评只能作为弱标签。随机抽查须记录已知且非零的选择概率。

错误率上界依赖样本与假设。作为样本量直觉，在独立同分布、固定规则、299 个独立接受对象均零错误时，单侧 95% 二项式上界约 1%；同题重复、选择性审核或自适应更新不自动满足这些条件。证据不足时只发布经验风险与覆盖率，不承诺普适保证。对应文档为 research-r5-prd.md、research-r5-technical-spec.md、ADR-0012。

## 九 组件组合与深入机制

先做有明确交互假设的组合，不做 32 种全排列。选择好的组件是工程决策；声称组合产生新的科学机制需要额外的消融与解释。

| 组合 | 交互假设 | 最小对照 |
| --- | --- | --- |
| R1 加 R2 | DE 表示帮助同一动作控制器选继续或改计划 | 直接 Q 与 DE 增强 Q，同动作、同数据、同预算 |
| R1 加 R3 | 路由选择工具后，失败分诊减少无效重试 | 固定回退与原因感知回退 |
| R3 加 R4 | 可信前提复用降低验证与重译成本 | 固定/学习分诊乘以无缓存/正确缓存的四格对照 |
| R2 加 R4 | 改计划时仍能保留有效证据 | 全重启、正确依赖缓存、预算恢复优化 |
| 最佳冻结系统加 R5 | 对最终交付质量提供可核查评估 | 固定审核、随机抽查、候选规则 |

若多个组件同时保留，在最佳组合上做逐个移除的消融，确认每项净贡献、重复验证成本与故障交互。统一一个预算调度器，避免多个元 Agent 互相调用形成额外回路。

每周一次证据复核只作开发决策。优先深化满足以下条件的 1–2 项：有跨题型效果、能解释作用机制、相对强基线仍有增量、实现维护成本合理。深入时新增版本化假设与配置，冻结上一阶段证据；不能修改旧阈值后把旧实验称为预注册验证。

## 十 停止动作与统计规则

停止分为单次请求、单题 Run、整批实验和研究主张四层。技术失败不能自动变成假设失败；不显著也不等于证明无效。

| 触发 | 立即动作 | 证据与恢复 |
| --- | --- | --- |
| 鉴权或权限失败 | 停止该批新请求，不自动切换模型 | 稳定错误类别；不记录凭证；配置修复后新批次 |
| 429 或暂时服务错误 | 全局退避，最多一次受预算重试 | attempts 全计入；连续失败达到配置阈值后暂停 |
| 客户端超时或服务截断 | 保留未知计量与不完整标记 | 不当作数学错因，不免费重置预算 |
| 单题或全批预算不足 | 停止新增调度，结算已知在途结果 | BUDGET_EXHAUSTED，保留部分产物并标待复核 |
| 用户取消 | 不再发新请求，终态不可被迟到结果覆盖 | CANCELED，已产生费用仍入账 |
| 工具域外或形式化失败 | 返回 UNKNOWN 或具体原因 | 按预注册规则回退，保留适用覆盖率 |
| 最终产物与验证哈希不符 | 撤销该产物的接受标记 | 重新验证或 NEEDS_REVIEW |
| 缺失成本或证据比例超过 5% | 暂停性能排名，排查采集层 | 不将 missing 变成 0，不删除失败样本 |
| 预定开发轮次无值得保留的收益 | 停止扩大该假设，保留有用工程 | negative 或 inconclusive 报告，关闭相应策略 |

数据有效性门先于性能门：协议混用、干预不成立、答案泄漏、模型版本变化等未解决时，不进入算法结论。开发期可频繁查看结果但只作探索性判断。冻结确认默认一次主要分析；需要分批查看时预先规定查看点与相应多重比较/序贯修正，不能反复查看普通 95% 区间并在首次显著时停止。

按原始问题聚类，给出正确率差、成本比、净修复率及置信区间。重复运行不是更多独立问题；无 seed 支持时称 repeat_id。策略、规则和预算只在 D-dev/D-cal 选择。最终测试出现失败、超时、无答案都保留为相应结局；“成功完成子集”指标只作辅助。

可采用两类预先确定的产品门槛：同等预算下正确率提升至少 2 个百分点且区间支持正向；或总成本下降至少 15%、正确率非劣界为下降不超过 1 个百分点且区间足以支持。阈值用于设计，不是小样本一达点估计就通过。若统计精度不够，保持实验性状态；具有明确界面或可追溯价值的组件仍可按工程门保留。

学术门还要求近邻对照、核心消融、跨题型或预算变化、真实失败案例与限制说明。只做 prompt 角色拆分、工具接入、状态命名或一般缓存，不单独包装为方法创新。

## 十一 证据归档与比赛交付

每个实验批次分配不可复用 run_id，绑定基线 SHA、实验 SHA、dirty 状态、协议版本、配置哈希、数据版本/分组哈希、模型信息与环境锁文件。正式确认拒绝 dirty 工作树。初始离线 setup 可以在工作树验证，但记录 dirty 状态，不把它当正式性能证据。

Git 中每个方向保留 PRD、ADR、技术文档、配置、脱敏指标、决策记录和归档索引；运行材料在 artifacts/<run_id>/ 或配置好的外部位置。外部归档须有稳定地址、内容哈希、访问说明与成功保存记录，不能仅留下已经失效的本地绝对路径。完整 prompt、题目答案库、隐藏推理、凭证、原始图片不进入 Git 或公开 Demo。

归档至少包含 manifest、attempts 用量表、按题结果、配对统计、故障摘要、适用范围、停止原因、回归记录、归档决定与复现入口。manifest 中的内容哈希可定位材料，公开索引不暴露凭证或带 token 的下载地址。回放只呈现允许的步骤与摘要，不触发模型调用，也不作为新的独立采样。

| 评分项 | 最有价值的可审查材料 | 交付标准 |
| --- | --- | --- |
| 系统设计 10 分 | 一条题目的规划、工具、验证、恢复与预算过程 | 每个事件真实对应行为，失败可解释 |
| 展示质量 20 分 | 稳定 Workbench、成功与失败录屏、技术报告、结果包 | 首次启动可复现，断线/取消/域外都有清晰交互 |
| 创新扩展 10 分 | 一项主机制、强基线与组合消融、模块接口 | 清楚说明比已有方案增加了什么和何时有效 |

比赛最小交付包含四类情景：普通文本题完整求解；适用工具题显示真实工具闭环；工具域外或验证未知显示限制；超时/取消/恢复显示已保存成果与实际状态。预录回放单独标记。视频与报告不展示隐藏推理或完整模型 prompt，只展示可公开的计划摘要、动作、工具结果范围与最终产物。

按一名主要开发者加研究审查者估算，以下为有效工作日而非比赛截止日期承诺。API 排队、形式环境和返工会改变时间；用户尚未提供比赛交付日，采用相对里程碑。

| 阶段 | 估算 | 应交付结果 |

| 第 2 阶段 | 2–3 个工作日 | B-ready、12 题成本试跑、配对 runner 和稳定演示脚本 |
